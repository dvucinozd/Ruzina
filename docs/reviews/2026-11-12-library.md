# JC1060: the Library page on the deck screen

Date: 2026-11-12. Branch: `ogranak/jc1060-library`, from `main` at `35a2f80`.

## Problem

The deck screen's LIBRARY tab only marked itself. To pick a track you had to rely on
the C load screen's hidden selection, which the Slint image never shows. The owner
asked for the Library first, with the browse knob moving only the list while that page
is open.

## Change

- **List:** at the catalog scan the media bridge hands the Library page each track's
  title, artist, key, BPM and duration, through a mailbox the UI task takes from.
- **Selection in Rust:** the selection lives in `deck_view` and stays within the list.
  - While the Library page is open, the browse knob moves it one row a detent, and
    Shift + browse ten rows.
  - On the Overview the knob still zooms the lanes, as before.
  - The UI task tells the engine whether the page is open.
- **Load:** LOAD on the controller, or the LOAD D1 / LOAD D2 buttons on the screen,
  loads the selected track onto that deck through the engine's existing load request.
  A playing deck still refuses a new track.
  - In the Slint image the old C path for browse and load (`ruzina_bridge_midi_ui`) is
    compiled out, so only one selection exists.
- **Page:**
  - 12 rows around the selection, with number, title, artist, BPM, key, time, and a
    D1/D2 tag for the decks holding the track.
  - It moves only when the selection leaves it. A tap on a row selects it.
  - It covers the lanes and meters, which Rust then stops drawing. The overviews and
    the deck rows stay visible.
  - Back on the Overview, the lanes and meters are drawn whole again in each buffer.
- **Build tool:** with `--slint-ui`, the deck-mix link check asks only for
  `ruzina_legacy_mix_stats`, because the old load entry point is no longer linked.

## Evidence

- **Host:** 3 new tests:
  - a touch LOAD survives the touch queue;
  - the selection stays within the list as it shrinks and grows;
  - on the Library page browse moves the selection and not the zoom, and LOAD
    requests the selected track on its deck.

  The legacy feature sets and target clippy (including `idf-slint-ui` and the profile
  build) pass.
- **Device:** s78 (app `9d776987…`), owner verdict "Radi".
  - The 15-minute capture: underruns 0/0, `packet_errors=0`, no panics.
  - Longest fill 6.0 ms with the soak DJ, within the accepted scratch exception.

## Test plan

1. Open LIBRARY: the list shows, and the lanes and meters are hidden.
2. Browse moves the selection one row, Shift + browse ten; the page follows.
3. Tap a row to select it. LOAD on the controller and on the screen loads it onto the
   right deck, and the D1/D2 tag appears.
4. Back to OVERVIEW: the lanes and meters return, and browse zooms again.
