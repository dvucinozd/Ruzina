## What is already available

The repository contains host-tested semantic controller/profile/session behavior; deck, mixer and Hot Cue logic; DSP/keylock/scratch primitives; media identity, partition discovery, native async read-only FAT32/exFAT and catalog machinery; Rekordbox PDB and ANLZ Hot Cue parsing; bounded WAV PCM16 source/transport and a fixed-rate software render graph. The historical target links storage/controller/render owners together under explicit legacy selection.

Both Guition profiles are independently represented and compile/link, but their [platform modules](../firmware-rust/apps/m1-firmware/src/platform/mod.rs) start only the scheduler. They do not start the product owners or activate display, touch, storage, USB or audio. Presence of a crate, successful linking, and an evidence class requested by the requirements do not establish an end-to-end product feature.

The functional reference remains the checked-in M2.2 contract in [product requirements](M1_RUST_PRODUCT_REQUIREMENTS.md). This review does not silently broaden that baseline to a later donor release.

## Owner audio routing clarification

After this review, the owner specified automatic MAIN preference for an available external DAC, with compatible controller audio as fallback, and clarified that headphones must always use the controller. The mandatory [headphone policy](M1_RUST_PRODUCT_REQUIREMENTS.md#8-controller-only-headphone-policy) closes that part of D2. Headphones remain on the controller when MAIN uses the external DAC; without compatible controller headphone audio, CUE is unavailable. No independent headphone DAC/amp is in scope. Physical output drivers and MAIN DAC detection/wiring remain open.

## Software gates

Follow-up implementation: [the PCM history/routing gate](M1_RUST_AUDIO_HISTORY_ROUTING_GATE_2026-10-20.md) implements S1's bounded live source path, S2's host routing contract and the initial diagnostic slice of S11. Physical sinks/pacing and complete subsystem health remain open. The table below preserves what was missing at the review baseline, rather than claiming these follow-up slices are still absent.

The [consumer-clock delivery follow-up](M1_RUST_SINK_DELIVERY_GATE_2026-10-20.md) adds S2's bounded PCM queues, frame requests, mute/fades and counters, integrated with the render graph in a headless simulation. The embedded reference task is unchanged; physical pacing, driver ownership and delivery-to-transport acknowledgement remain open.

The [completed-output progress gate](M1_RUST_PLAYBACK_PROGRESS_GATE_2026-10-21.md) subsequently connects S2's delivery-to-transport acknowledgements in the reference target and canonical host simulation. It adds ordered completion receipts, source-bound resets and MAIN/headphone authority. The reference task still has software timing; physical adapters, actual completion/clock semantics and audio acceptance remain open.

The [pinned Rekordbox analysis gate](M1_RUST_REKORDBOX_ANALYSIS_GATE_2026-10-21.md) adds S5's classic DAT/EXT grid, monochrome waveform and source Hot Cue import with immutable generation-bound publication. The legacy product passes loaded analysis into its deck consumers; host fixtures and three pinned public pairs verify parsing/semantics. Newer ANLZ formats and physical/resource acceptance remain separate gates.

The [interactive UI follow-up](M1_RUST_INTERACTIVE_UI_GATE_2026-10-21.md) replaces S6's static host screen with real deck actions/state, demo Library, effective Hot Cues, session Settings and RGB565 waveform composition. Two board-size replays and 14 reviewed pixel goldens cover that slice. Full M2.2 UI parity still needs mixer/FX/diagnostics/performance views, arbitrary media/catalog integration, durable settings and physical Guition display/touch/resource acceptance. The historical review table below remains the original baseline.

## Explicitly deferred scope

- Native APTA stays unmerged by owner instruction. The provider-neutral Rekordbox path remains developable independently. Reconsider APTA only with separate upstream/release and resource evidence plus owner authorization.
- Ordinary folder libraries, tag readers and transactional `/PAJONIIIR` sidecars/playlists remain SHOULD work. They should follow the reliable core source/analysis/storage contracts rather than expand the first audible milestone.
- Recorder and SysEx/MIDI-CI remain LATER. Secure Boot/Flash Encryption pilot qualification remains SHOULD and must not become an accidental first-bring-up requirement. Controller-independent headphone hardware is excluded by the owner clarification above.
- Custom PCB routing, Gerbers, manufacturing closure and fabrication are discontinued milestones. Historical INA238/PCM5102A or independent VBUS requirements need an explicit Guition disposition, not an assumption that those components exist on the purchased boards.

## Recommended execution order at the review baseline

1. While boards are in transit, start S1: canonical PCM history and source arbitration with deterministic host fixtures. Develop S2's sink contract alongside it, without choosing unverified board pins or output hardware.
2. In parallel work streams over time, close S5's Rekordbox analysis publication and S6's interactive simulator; choose D2's MAIN/PFL route and prepare board diagnostic logging. Resolve Q1 at account level.
3. On arrival, choose D1 and close unit identity, recovery, panel/touch and USB mapping/power observations. Implement each adapter under S7 independently; establish memory/cache/display budgets before integrated audio load.
4. Prove the first audible milestone: one WAV PCM16 source, stable real sink cadence, stereo MAIN/PFL routing as agreed, no false support claim. Then dual deck, S3 live performance modes/FX, S4 MP3/FLAC and combined-load acceptance.
5. Complete settings/write transactions, OTA/boot health and C6/Web Remote, then close the per-requirement and exact-image release campaigns. This ordering does not remove any R1 MUST gate.

S1's software history/arbitration path and the host routing/first-boot preparation are now implemented in the linked follow-up gate. The next physical milestone is exact-unit service/recovery and memory/peripheral bring-up followed by real I2S/UAC output. Loop/FX, decoder, analysis and interactive UI work remain independent host development paths. None requires merging APTA.
